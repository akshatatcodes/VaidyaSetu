# MEDIKIOSK / VAIDYASETU

## MASTER IMPLEMENTATION BLUEPRINT FOR VIBE CODER

You are working on an existing Node/Express + MongoDB + React/Vite healthcare platform.

The repository currently contains two overlapping concepts:

1. An older VaidyaSetu wellness application.
2. The new MediKiosk hospital workflow platform.

The target is to turn the repository into one coherent, production-structured MediKiosk platform.

The existing source bundle contains 224 files, including backend AI services, models, routes, patient/doctor/lab/admin pages, kiosk components, tests and localization files. Do NOT assume the repository is clean or that existing “100% complete” claims are correct. Inspect the actual implementation before changing it.

---

# 0. ABSOLUTE RULES

These rules apply to every phase.

## Rule 1 — Do not invent a second architecture

The target architecture is:

Patient
→ Identity
→ Consent
→ Health Profile
→ OPD / Kiosk Intake
→ Encounter
→ Queue
→ Doctor
→ Investigation
→ Lab
→ Result
→ Follow-up
→ Referral
→ Longitudinal Timeline
→ ABDM/HIS

Every clinical event must be anchored to an Encounter.

Never randomly attach clinical data directly to Patient when that data belongs to a visit/clinical interaction.

The normalized target model already defines Encounter as the central object.

## Rule 2 — Role isolation

There are exactly four application roles plus a separate kiosk experience:

* Patient
* Doctor
* Lab Technician
* Hospital Admin
* Kiosk Terminal

Each role gets its own navigation, dashboard and route namespace.

Never expose another role's navigation or dashboard.

## Rule 3 — Dashboard is not the entire application

A dashboard should show:

* what matters now
* current workload/status
* the most important next actions

It must NOT contain every feature.

Detailed functionality belongs in dedicated pages.

## Rule 4 — One route = one responsibility

Do not use a giant dashboard with internal tabs when the content represents a distinct operational page.

## Rule 5 — Kiosk is a different UI shell

The kiosk must never use the normal patient sidebar.

## Rule 6 — AI does not diagnose

AI:

* collects
* structures
* summarizes
* routes
* detects red flags
* predicts queue timing
* extracts documents

The doctor remains responsible for diagnosis, prescription and clinical decisions.

The existing architecture explicitly requires doctor review before encounter closure.

## Rule 7 — Never fabricate missing clinical information

Valid information states:

* Confirmed
* Patient reported
* Caregiver reported
* Document derived
* Uncertain
* Conflicting
* Not reported

Never convert “not asked” into “no”.

## Rule 8 — Preserve source provenance

Every extracted clinical value should retain its source.

Examples:

* Patient reported
* Caregiver reported
* OCR/document
* Doctor entered
* Lab result
* Kiosk device

## Rule 9 — Do not destroy existing data during migration

If old IntakeSession data exists, migrate it into the new Encounter-centered model.

The existing migration plan already specifies:

IntakeSession
→ Encounter

* History
* Vital
* Document
* InvestigationOrder
* LabSample
* LabResult
* Prescription

rather than deleting old records.

## Rule 10 — Every phase must pass acceptance checks before the next phase begins.
